## 进入对战

1. 从标题页进入模式页。本地双人和人机对战可选「标准对战」或「双角色车轮战」，也可以单独进入自由训练。
2. 标准对战各选一位，车轮战各选首发和后援，两队确认后才进入选图。可选角色有大肥鱼、奶蛙、香蕉猫和姑姑嘎嘎，两队可以使用同一角色。
3. 选地图。默认场地是直播擂台。直播擂台只有连续地面；其他地图可点「登台路线」查看登高路线。标准局为每回合 60 秒、先赢两回合，可在选图页调整。
4. VS 开场会显示阵容、场地和规则。结算页逐段记录结果，支持保留规则与阵容再战，也可以换人、换图或返回模式。[双角色车轮战规则](docs/双角色车轮战.md)

单人验证地图时可直接选**自由训练**。展开左下「训练设置」可查看实际落脚的平台名称和已到达的最高层。陪练可静止、防御、重复直拳或跟随，训练支持半速。暂停后可前进一帧，按 R 可以重置。给角色接入精准防反后，用「重复直拳」和 H 面板可以核对生效窗口与反击动作。[防反接口与试招方法](docs/character-handoff.md#防反接口)

实战界面将生命、耐力和胜场标记收在上缘，三段气槽位于下缘两侧。受击后的尾条短暂保留近期损失，连击计数显示在屏幕侧边。按 H 打开调试时可查看生命和耐力数值。防御耐力按来招的 `guardCost` 削减，耗尽会破防。训练中展开「训练设置」选择陪练、慢放或充气。

## 好友联机

进入「联机对战」创建房间，好友输入房间码加入。连上后双方在游戏内选择并确认自己的角色。房主可以在选角页切换单角色对战或双角色车轮战。本地双人和人机模式也可在选角页切换赛制。双方确认后进入地图页，由房主选地图和时长，再按「开始对战」。单角色可以设置先赢几回合，车轮战每场淘汰败方角色。双方使用各自的 P1 键位，一方离开会结束房间。

本机验证用 `npm ci` 和 `npm run build` 构建，在两个终端分别运行 `npm start` 和 `npm run start:online`，然后用两个浏览器窗口打开 [本机游戏](http://127.0.0.1:4182/)。

自建公网 Linux 服务器单端口联机时，运行 `npm ci && npm run build:site && npm run start:public`（默认监听 `0.0.0.0:4184`，可用 `ONLINE_PORT=80` 改端口），在同一端口同时托管 `site/` 静态网页与 `/match` 联机服务，安全组放行对应端口即可通过 `http://服务器公网IP:4184/` 直接联机。

部署到 Qoder Sites 时，网页和联机服务使用同一份提交。

1. 在支持长连接的 Node.js 主机运行 `npm run build` 和 `npm run start:online`。用 HTTPS 反向代理转发 `/match` 的 WebSocket 升级请求到该服务，默认端口为 `4184`。`ONLINE_HOST` 和 `ONLINE_PORT` 可覆盖监听地址与端口。
2. 将 `ONLINE_ORIGINS` 设置为实际 Qoder 站点的 HTTPS origin，例如 `https://game.example.com`，多个地址用逗号分隔。预览地址和正式地址不同时分别登记。
3. 网页构建时设置 `ONLINE_SERVICE_URL=wss://rooms.example.com/match`，运行 `npm run build` 后由 Qoder 发布 `dist/index.html`。使用正式站点地址邀请好友。

联机服务的 `/healthz` 用于检查进程是否就绪。联机房间只保存在内存中，服务重启会关闭现有房间。部署后请用两个独立浏览器打开正式地址，检查建房、加入和双方血量同步。

## 公共按键

| 操作 | P1 | P2 |
|---|---|---|
| 左右移动 | A / D | ← / → |
| 防御 | S | ↓ |
| 跳跃 / 二段跳 | K | 右 Shift 或小键盘 2 |
| 逐层下穿 | S + K | ↓ + 右 Shift |
| 地面 / 空中冲刺 | L | Enter 或小键盘 3 |
| 普攻 / 空中攻击 | J | 逗号或小键盘 1 |
| 地面挑空 | W + J | ↑ + 逗号 |
| 主动进攻／远程优先 | U | 句号或小键盘 4 |
| 角色特色机制 | I | 斜杠或小键盘 5 |
| 战术大招（一格） | W + O | ↑ + 单引号或小键盘 6 |
| 代表大招（三格） | O | 单引号或小键盘 6 |

各角色连段由角色包定义：大肥鱼三段尾击、奶蛙掌击、香蕉猫四段和姑姑嘎嘎五段。姑姑嘎嘎和香蕉猫可预输入连续普攻；命中、格挡或打空均按各自接续窗口推进。普通挑空与空中受击会持续失控到落地，但空中仍可被追击；落地后经过倒地和起身，结束后恢复操作。公共倒地与起身合计约 0.8 秒，期间不能移动或出招。前两段也能接挑空。以 P1 为例，按 J 命中、W + J 挑空、K 起跳、J 空中追击。打空或被防住时要等收招。每次离地可在二段跳和空中冲刺之间选一次，落地恢复。

从台面下方起跳，在下降经过台沿时落脚，空中可以左右调整。按住下方向再跳跃会从脚下的平台向下掉一层。Esc 暂停，H 显示判定框与台沿。在自由训练中，H 还会显示双方所处的动作阶段、剩余帧数和最近四次按键。选角的方向键和确认键可在「设置」内修改，操作说明会一起更新。同键冲突会提示。全屏受容器限制时，「全屏」会切换到窗口内放大。

P1 默认使用 J 普攻、W+J 挑空、U 主动进攻、I 特色机制、W+O 战术大招和 O 代表大招；P2 使用当前设置中对应的重绑键。同类招式放在一起。大肥鱼 U 投饭，I 放推进旋风，W+I 放定点旋风，S+I 放护身旋风。普通 J/U/I 不消耗杀气。自由训练中展开「训练设置」可充满三格气。香蕉猫的眼泪值在血条下方，长按 I 回泪，地面满三格时按 W+I 觉醒；姑姑嘎嘎在地面/空中按 I 分别部署两类炮台。具体设计由角色负责人维护。

## 接入正式技能

已合并四位角色实现。四个角色文件各自拥有 `stats`、`art`、`signatureMoves` 和公共招式命中衔接配置。源码内部继续用 B/C 表示 U/I 两个动作槽，但玩家界面、招式表和交接验收统一使用实际键位与战术职责。现有普攻、技能、大招、语音和特效来自队友分支；后续继续在各自角色包迭代，构建会检查并打入离线版本。自由训练链接支持 `p1` 和 `p2` 指定两个角色。[角色文件](src/content/fighters) · [接口与示例](docs/character-handoff.md) · [奶蛙对香蕉猫训练](http://127.0.0.1:4182/?practice=harbor&p1=frog&p2=banana)

杀气最多存三格，每格 100 点，默认通过命中和承伤积累，只供大招使用。普通 J/U/I 及方向变式固定零杀气；强度由起收手、冷却、实体上限或眼泪等专属资源控制。当前四角均以 O 释放三格代表大招、W+O 释放一格战术大招，未登记的 S+O 不会回退成其他招式或扣气。训练中展开「训练设置」，点「充满三格能量」补到 300 点，用 H 面板与半速核对出招。[杀气与大招接口](docs/character-handoff.md#技能能量) · [下载试招样例](https://github.com/haoabcde/meme-rumble/releases/latest/download/ultimate-demo.html) · [本机试玩](http://127.0.0.1:4182/ultimate-demo.html)

角色可以配置逐帧攻击框和受击框、多段命中组、独立飞行或驻留实体，以及命中特效、震动和声音预设。组合输入用逻辑按键声明，方向修饰和键位重绑共用现有输入层。构建会生成独立的 `dist/combat-demo.html`。[战斗接口交接](docs/character-handoff.md#逐帧判定组合输入与命中表现) · [本机试招](http://127.0.0.1:4182/combat-demo.html)

角色包还可登记音效和语音文件，用 `audioTimeline` 按动作帧播放，用 `feedback.audio` 配置命中声；公共普攻也可按角色更换音频。支持受击打断或继续播放、双方独立语音、暂停及总音量／音效／角色语音调节。文件随离线版内嵌，正式素材由角色负责人提供。[音频交接](docs/character-handoff.md#音效与角色语音) · [本机音频联调](http://127.0.0.1:4182/audio-demo.html) · [下载联调页](https://github.com/haoabcde/meme-rumble/releases/latest/download/audio-demo.html)

技能的射程、影响高度与位移按世界坐标设计。场地左右边界用 `arena.left` 和 `arena.right`，地面高度用 `arena.floor`。1280×720 是镜头画布尺寸，镜头平移和缩放独立于战斗判定。

## 地图、美术与运行

- [场地数据](src/content/arenas.ts) 定义出生点、可走边界和登台路线。[货港布局](src/content/harbor.ts) 把货柜、步桥、渡船、值班室与吊盘的落脚线放进同一份数据。选图预览、实战与训练都使用这些坐标。
- 单层直播擂台使用一套连贯的背景与垫面；四张多层场地使用远景、建筑图集和独立动态物体绘制。建筑台沿、预览路线和实战落点使用同一份坐标，吊盘与升降机随战斗帧推进。[校园场景绘制](src/web/stage-art.ts) · [货港绘制](src/web/harbor-art.ts) · [移动平台轨迹](src/core/terrain.ts) · [资产制作记录](assets/README.md)
- [角色资产](assets/fighters) 中的 `*-motion.webp` 包含跑动、起手、不同攻击、格挡、收招与受击姿势。姿势按战斗状态和动作帧切换。 [动作图集规格](assets/README.md#公共动作图集)
- TypeScript 固定 60 Hz 战斗内核、Canvas 2D 渲染、Web Audio。默认使用同屏跟随，设置里可以切换近身特写。 [镜头计算](src/web/camera.ts)

开发需要 Node.js 20 或更新版本。可用 `npm run package:characters` 生成单文件和 ZIP 游玩包；生成后的游戏为当前主分支的四角色合并版。

```sh
npm ci
npm run build
npm test
```

开发调试可用 `/dev.html`，以及 `/frog-review-dev.html` 查看奶蛙所有人物姿态；它们从本机服务加载脚本，避免调试工具处理过大的内嵌页面。正式离线文件仍为 `dist/index.html`，内嵌所需图像、音频、样式与脚本，可以单独拷走。[详细验收记录](design-qa.md)
