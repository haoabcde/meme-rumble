## 三、两边设计冲突与接入隐患清单（对照 `v0.2` 规范）

### 1. 【P0】按键槽位与“大招契约”冲突
- **香蕉猫按 `I` 耗气变身破坏“只有 `O` 耗杀气”公约**  
  主线规定 `J/U/I`（内核 `A/B/C`）固定零杀气，`O` 为三格代表大招、`W+O` 为一格战术大招。目前香蕉猫在未觉醒且满 300 气时，按 `I` 本意是哭泣回泪，却会被 `tryStartJoAwaken` 直接截走清空 3 格气；同时 UI 大招提示灯（[game.ts](../src/web/game.ts) `buildUltimateCues`）和出招表按 `slot: 'ULT'` + `direction` 识别，无法直观提示“`300` 气按 `I` 变身、变身后再按 `O` 时停”。
- **咕咕嘎嘎 `U(B)` 槽过载，且引入独有的 `后+U` 与 `S+U` 防反**  
  嘎嘎将剑波(`U`)、碎晶(`W+U`)、防反(`S+U`)、抛杆(`后+U`)、空投(`空U`)、断空俯冲(`空S+U`)共 6 招全部堆在 `U` 键：
  1. `后+U` 引入了其余三位角色和简化招式面板几乎不用的 `direction: 'back'`；
  2. 防反放在 `S+U`，与大肥鱼（地面长按 `S` 宽盆防反）、奶蛙（`I` 特色架势）操作语言不一致。

### 2. 【P0】资源公平性、霸体/时停时长与数值强度失衡
- **哭泣站桩每秒回 1.2 格气**：[match.ts](../src/core/match.ts#L1785-L1788) 中 `cryEnergyPerTick = 2`（且 `cry` 通道帧数停在 `0` 每帧累加），导致香蕉猫站在角落哭 2.5 秒就满 300 气直接觉醒/开大，与大肥鱼/奶蛙必须靠命中、挨打或绕背成功积攒杀气的节奏严重背离。
- **永久 JO 形态 vs 奶蛙 15 秒限时天使**：奶蛙开大仅有 15 秒强化期且结束归回常态；香蕉猫变身后**整回合永久常驻**，配合 `枯萎穿心(+28 气)`、`空压连殴(+12 气)` 高效自回气，还能再连出 `世界·时间停止`。
- **回气权重反向**：大肥鱼/奶蛙沿用 `onHit: 20 / onHurt: 10`，嘎嘎和香蕉猫设为 `onHit: 12 / onHurt: 18`（鼓励挨打多于鼓励进攻），全员回气规则口径未对齐。
- **高频小技能 `unblockable`（无视格挡）与超时停压制**：除 3 格代表大招 `帝江` 外，嘎嘎小技能引爆 `敕令碎晶`(128 伤)、香蕉猫小技能 `起爆硬币`(115 伤) 和 `世界·时停`(4.1 秒全屏冻结 + 必中 260 伤，时长约为帝江/水潭演出 3～4 倍) 均带有无视格挡属性。
- **嘎嘎炮台全零耗气**：双管炮塔、榴弹炮与供电桩目前均不消耗任何气或专属冷却资源，叠加供电桩双倍射速后场控压制强度需要队内统一评估。

### 3. 【P1】统一连段接口断链与现存跨回合 Bug
- **JO 形态破坏了统一空追路线**：主线 `v0.2` 统一路线为 `J（前1~2段命中） → W+J 挑空 → K 跳取消 → 空中 J`。[game.ts](../src/web/game.ts#L498-L506) 招式表甚至会自动检测该链条是否接通。咕咕嘎嘎与常态香蕉猫已符合，但香蕉猫进入 **JO 形态后**：`joJab/joCross/joPounce` 只配置了 `cancelOnHit: ['C']` 没有 `joLift`、`joLift` 未配置 `'jump'` 取消、空中 `J` 会强制替换成 `白金流星俯冲`，统一追击体验中断。
- **代码核对发现的两处遗留 Bug**：
  1. **供电桩回合重置遗漏**：[match.ts](../src/core/match.ts) 的 `resetMatch` 清空了 `state.powerPylons = [null, null]`，但 **`rampToNextRound`（回合切换）与 `timeStop` KO 分支仅重置了 `state.turrets`，漏掉了 `state.powerPylons`**，第一回合结束前放下的供电桩会延续至第二回合。
  2. **UI 提示键名笔误**：[game.ts](../src/web/game.ts#L90) 的 `moveUses` 把帝江动作 ID 误写为 `'gaga-dijiang'`（实际 ID 为 `'gaga-summon-dijiang'`），导致用法说明未匹配生效。

### 4. 【P1/P2】工程结构耦合、AI、音频与测试现状
- **公共内核耦合偏重**：主框架与大肥鱼/奶蛙把专属规则放进 `whale-kit.ts` / `frog-kit.ts` 和通用 `entities` 管线；而目前嘎嘎和香蕉猫将 `tryStartJoAwaken`、`joAwakened`、`joReplacement`、`timeStop`、`bombMark`、`crystalMark`、`powerPylons`、`gaga-xiranite-burst` 事件硬编码、四槽 `turrets` 等大量逻辑直接写进了核心 [match.ts](../src/core/match.ts) 与 [types.ts](../src/core/types.ts)。
- **AI 未跟上新招式**：[cpu.ts](../src/web/cpu.ts) 对香蕉猫仅会常态哭泣/喷泪/普通 `O`，**不会发动 JO 觉醒及所有 JO 形态招式**；对咕咕嘎嘎也仅做了零散几条碎片判定。
- **音频管线未统一到 `fighter.audio` + `audio-levels.ts`**：大肥鱼、奶蛙已全面纳入 `fighter.audio`、`audioTimeline` 与 [audio-levels.ts](../src/web/audio-levels.ts) 7 级 RMS 校准；而香蕉猫 6 个 MP3 仍通过 [audio.ts](../src/web/audio.ts) 里的 `__BANANA_SOUNDS__` 独立旁路与手写倍率播放，咕咕嘎嘎也混用 `__GAGA_SOUNDS__` 硬编码、尚缺 `victory-lalala.wav` 与新增招式配音。
- **当前验证边界**：联机依赖 `ws` 安装及全套 `npm test` / 双机联机回归暂未执行；工作区尚有咕咕嘎嘎防反表现补丁（[art.ts](../src/web/art.ts)、[gaga-fx.ts](../src/web/gaga-fx.ts)、[renderer.ts](../src/web/renderer.ts)）待团队口头/规则一致后统一落仓验收。

## 四、给队长的协调方案与待拍板清单

建议由队长按下面 **4 个决策点**定调，我方随后立刻按结论完成改建、拆解与测试提交：

1. **【决策 1】香蕉猫与咕咕嘎嘎的按键定调**
   - **香蕉猫 `JO化觉醒` 归位（二选一，强烈建议不占用 `I` 键）**：
     - *推荐方案 A*：保留 `I` 纯作哭泣回泪 / 炸弹操作（零杀气）；将 `JO化觉醒` 移入 `O` 系大招（例如常态 3 格 `O` 放 `泪海滔天`、**启用 `S+O` 3 格发动 `JO化觉醒`**，并把 [game.ts](../src/web/game.ts#L68) 已预留的 `thirdUltimate` 提示正式开放；或把 `泪海滔天` 调为 1~2 格战术型、`O` 专职觉醒与时停）。
     - *备选方案 B*：如决定取消“三格切永久形态”，可讨论直接将 JO 觉醒做成对标奶蛙的 **3 格 `O` 限时大招**（变身+连招自带时停终结或限时强化，不再叠套 3 个三格大招）。
   - **咕咕嘎嘎 `U / I` 减负**：
     - 建议**删除或合并 `后+U` 投杆**（避免全游戏仅此一角使用 `direction: 'back'`）；
     - 请队长定夺**息壤防反**是保留在 `S+U`（同步放进简化招式提示条）还是挪至 `I` 特色槽位 / 对接公共 `guardCounter` 接口。
2. **【决策 2】资源公平性与超模项收口**
   - **立即取消香蕉猫哭泣回气**（`cryEnergyPerTick = 0`），恢复“只回眼泪、靠实战对抗攒气”；
   - 请明确 JO 形态是否改为**限时强化（如 15～20 秒）**，或保留回合常驻但取消 `枯萎穿心(+28 气)` / `空压连殴(+12 气)` 的额外杀气返还，并将 `世界·时停` 冻结时间由 `246` 帧（4.1 秒）缩短到 `90～120` 帧（1.5～2 秒）；
   - 请明确 `敕令碎晶`（128 伤）与 `第一炸弹·起爆`（115 伤）是否取消 `unblockable`，改为高 `guardCost` 破盾效果；以及咕咕嘎嘎 `I` 炮台是维持 `0` 气加冷却，还是恢复 1 格杀气/总数量限制；
   - 统一全员基础 `onHit / onHurt` 杀气比例（建议全员统一 `20 / 10`，或由队长批准个别角色差异数值）。
3. **【决策 3】统一公共路线与遗漏修复**
   - 补齐香蕉猫 JO 形态的 `W+J → K → 空中 J` 空追兼容性（或确定保留豁免）；
   - 一并修复 [match.ts](../src/core/match.ts) `rampToNextRound` 漏清 `powerPylons` 与 [game.ts](../src/web/game.ts) `'gaga-summon-dijiang'` 命名笔误。
4. **【决策 4】工程收敛与联调收尾顺序**
   - 第一步：队长拍板上述第 1、2 项规则口径；
   - 第二步：我方按结论收敛按键、数值与设计文档，参照 `whale-kit.ts` / `frog-kit.ts` 将嘎嘎与香蕉猫专属状态从 `match.ts` 抽离；
   - 第三步：将香蕉猫 6 条音频、嘎嘎现存 17 条与后续新增“咕咕嘎嘎”人声一并迁移到 `fighter.audio` + `audio-levels.ts` 统一音轨体系，并完成 AI 补全、`npm test` 回归及联机双端实机验证。
