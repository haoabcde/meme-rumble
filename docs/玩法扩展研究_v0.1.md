# 玩法扩展研究

研究日期：2026-11-24。本文为玩法提案与接入分析，尚未实现或进行新模式试玩。参数均为首轮原型假设，不是已验证的平衡数值。角色外形、招式和组合技继续由角色负责人设计。

## 现状与判断

当前页面有本地双人、人机和自由训练三个入口，但它们主要改变对手与练习条件。正式对局仍以击败对方、超时比较生命决定胜负。五张地图包括连续单层直播擂台，以及带登高路线和移动平台的货港、楼顶、球场和电站。

从规则与结构推断，大地图若长期只有消耗生命这一项目标，可能出现追逐、拉远和围绕固定优势位置反复交战。新增玩法应让玩家有主动争夺或转移的理由，并保留现有移动、格挡、打击与角色技能。

当前 `MatchConfig.fighters`、`MatchState.fighters`、胜场及结算使用固定双席位。每侧轮换角色可以在两人战斗之上增加外层赛制；四人同时登场和双人合作打多名敌人则涉及更深的战斗内核改造。召唤物接口不等于已经支持任意数量的完整角色。

## 参考中值得借鉴的机制

- 《任天堂明星大乱斗 特别版》提供逐人出场的 Squad Strike、经典路线、训练及击飞沙袋挑战。可借鉴同一套战斗操作支撑不同赛制与短挑战；本项目只有四位角色，首版更适合每侧两人的车轮战，而非照搬原作三人或五人规模。[任天堂官方模式说明](https://www.smashbros.com/en_GB/howtoplay/mode.html)
- 《Brawlhalla》夺旗要求把旗带回基地，受到伤害会掉落，得分条件也要求本方旗在基地。这体现了携带目标、拦截和回收能够改变移动选择。本项目可先做双人争夺中立物件，规则与原作三对三夺旗有所不同。[官方夺旗说明](https://www.brawlhalla.com/news/return-to-demon-island-explore-new-features-patch-6-11)
- 《TowerFall》有限箭矢可被回收，宝箱中的道具吸引玩家冒险移动，最后击杀还有即时回放。可借鉴场景资源引发的攻防选择，以及回放帮助玩家理解胜负；不直接移植其武器体系。[官方玩法介绍](https://www.towerfall-game.com/)

以下规则与主题为本项目提案，不是对参考游戏规则的逐项复制。

## 八个方向

| 玩法 | 玩家做什么 | 地图作用 | 相对改造量 |
|---|---|---|---|
| 抢热点 | 占领轮换的目标区域，争夺积分 | 把登高、换边和近身驱赶变成明确目标 | 中：目标状态、计分、复活、提示与结算 |
| 双角色车轮战 | 每人选择两角，按顺序出场 | 同一场地承接连续对抗 | 低至中：阵容队列、资源策略和换人清场 |
| 抢梗带货 | 抢中央物件，带回自己的交付区 | 上下路线成为运输和拦截线路 | 中至高：携带、掉落、归位、交付和位移联动 |
| 操作挑战 | 限时跑图、移动靶命中、防御和连段练习 | 现有平台路线成为可重试的小关卡 | 低至中：挑战脚本、检测、计时和成绩 |
| 街机路线 | 连续击败对手，选择下一张地图或挑战条件 | 五张地图形成一条可重复游玩的路线 | 中：赛程、AI条件、路线和存档 |
| 主题事件局 | 应对有预告、可绕开的场景变化 | 灯光、吊盘、升降机承担规则作用 | 中：事件状态、预告、逻辑碰撞与独立开关 |
| 击球擂台 | 用攻击把公共球体送入对方得分区 | 球场或直播馆获得专门的趣味规则 | 中至高：球体物理、攻击交互和防重复计分 |
| 双人合作／四人乱斗 | 两人协作打敌人，或多人同场对抗 | 多个方向的威胁与更宽的镜头需求 | 高：多角色、阵营、命中关系、输入与镜头 |

相对改造量依据当前代码结构判断，不代表开发工期。前三项各有独立价值，原型不必同时上线。

## 推荐首个原型：抢热点

目标是让大地图自然产生转移和争夺。最小原型采用本地双人，先在夜训球场运行；目标型AI另行接入，不能让原来只会追人的AI冒充懂得占点。

### 一局怎么进行

1. 地图预先指定三个可抵达的位置：中圈、左侧转播席、右侧看台。热点属于已有地面或建筑台沿，不新增无支撑横条。
2. 一个热点生效20秒，提前3秒提示下一个位置，顺序固定。相邻目标先按约4秒内可转移的路线选择，避免强迫玩家横穿整张地图。
3. 只有一方站在热点对应落脚面内时，每秒获得1分；双方都在时停止计分。站着防御可以占点，空中经过不立即获得占点收益。
4. 首轮假设为先到60分获胜、上限120秒。HP归零后等待3秒在安全侧重生，不直接输掉整局；KO用于暂时夺走对方的占点资格。
5. 超时比较积分；同分加时固定当前热点，连续独占3秒决胜。加时上限30秒，仍无胜者则平局。

这些时间和分数要通过试玩调整。第一轮只验证“是否愿意移动、能否看懂争夺、落后方能否重新争取目标”。

### 界面与公平性

- 保留两侧生命、耐力和三格气槽；中央显示双方积分及剩余时间，热点只显示必要的边界与下一处方向。
- 用落脚面ID与脚部位置确定占点，避免上方屋顶和下方地面投影重叠却同时算占点。
- 大招演出、命中停顿与暂停期间，模式计分、热点轮换和复活倒计时应与有效战斗时钟一致，画面层不自行计时。
- 出生保护期间不能计分；在热点之外设置安全出生点，最近的重生点不能直接落在目标区。
- 全图攻击、瞬移与炮台原有设计保留。它们是否导致无法争夺，应先用真实角色对局记录判断；炮台和召唤物本身不计为占点者。
- 可移动平台不用于第一版热点，先避免目标区域跟随、路线同步和支撑丢失的问题。

## 最适合利用四角色的赛制：双角色车轮战

双方各选两个不同角色并确定顺序，双方之间允许选择相同角色。场上始终各有一个角色，打完一个再换下一个；队伍全部退场才判负。这里的“两角”不是四人同时战斗，也不是主动换人连招。

第一版可验证“胜者保留剩余HP、无自动回血、替补满HP入场”。新交战段双方通用能量归零，所有攻击、束缚、临时强化、场上实体、炮台、召唤物和输入缓存清理。眼泪等角色专属资源采用角色声明的初始值。保留到下一段的内容必须列入白名单，不能简单保留整个旧状态。

首轮假设为每次交战段60秒，超时按当前出场者生命比例判胜，负方当前角色退场；等比例或同帧双KO则双方当前角色一同退场。两队同时耗尽则整场平局。换边与暂停也需覆盖。允许车轮战消耗胜者HP，但是否继承通用能量是另一项平衡变量，第一版不把两者同时开放，以便定位问题。数值结论必须通过试玩，不宣称“选两个人就已经平衡”。

## 第二阶段的地图玩法：抢梗带货

货港中央出现一个中立物件，两侧各有交付区。接触拾取，带回本方区域并停留1秒得分，先交付3次获胜。物件外观可先用普通包裹占位，最终梗素材另行决定。

受到实际伤害、被击倒或主动放下时掉落；仅格挡成功不掉落。掉落物10秒无人拾取则回中央。拾取、掉落和交付使用独立状态，防止同帧双方拾取或重复计分。

奶蛙的瞬移会影响运输距离，需要模式层的明确规则：持物者发动瞬移或绕背时，物件先留在出发位置，角色技能照常执行。规则对所有同类空间跳转统一处理，不仅给某一角色加限制。普通跑跳、冲刺可以运输；是否允许带物空中冲刺留待测试。

瞬移不是唯一风险：全图攻击可能反复打落物件，炮台可能长期守交付区，强位移可能造成快速运输。需要记录真实夺取、掉落、交付过程，确认是否仍有反制机会；不能只做三个得分动画就认定玩法成立。

## 其余方向怎样做得有用

- **操作挑战**：先做一条货港跑跳路线、一次限时靶位挑战、一组格挡反击练习。按角色可达性提供不同目标，不要求缺少远程的角色完成同一远程靶。成绩记录时间、失误和完成条件，不只显示总伤害。
- **街机路线**：先用现有角色AI逐场交战，选择下一张地图和公共挑战条件。早期不加入随机改写角色技能的成长树；有趣与否先看路线选择、连续挑战和失败重试。
- **主题事件局**：每图只测试一种事件，例如球场探照灯区轮换、货港吊盘按预告改变运行节奏、电站升降机进入短暂锁定。必须可预判、有替代路线；标准对战保持独立开关。
- **击球擂台**：首版只让普通攻击影响球体；同一攻击组只作用一次，球速有上限，卡住可重置。远程、多段实体和全图攻击如何影响球体另做规则，避免自动炮台永久连球。不要把球当普通角色HP结算。
- **合作和四人同场**：需要先把双席位结构、角色归属、友伤、锁定、重生和镜头做成多角色规则。Boss形象与专属招式要有独立负责人；现有召唤物能力不足以证明合作模式已经可行。

## 接入边界

将“谁来操作”与“如何获胜”分开：本地／AI／训练是参与方式；标准对战／抢热点／车轮战是比赛规则。页面不必为所有组合都新增一张菜单。

新规则以模式配置和可序列化状态承接：目标、积分、阵容、复活、赛程与事件由战斗逻辑推进；渲染器只画结果。继续使用固定战斗帧、统一命中事件和角色接口，避免在渲染分支计算得分，也避免增加只识别奶蛙或嘎嘎的玩法代码。

原型至少覆盖：同帧事件顺序、暂停及演出冻结、双KO、目标归位、重生保护、生成物清理和重开。带随机规则时保存种子；模式状态需要进入现有快照和重放范围。

## 建议推进顺序与试玩门槛

1. 先做一张地图的抢热点，观察地图路线是否开始产生攻防选择；若要先交付改造量更小的赛制，可先做双角色车轮战。
2. 加入操作挑战，给独自试玩和队友验招提供持续内容。
3. 基于已经稳定的目标、重生和得分模块做抢梗带货。
4. 主题事件与击球作为趣味内容，再考虑合作／四人同场。

每个模式至少实玩三组：双方主动争夺、一方持续远程或守点、一方落后尝试反攻。记录争夺发生的位置、无意义跑图时间、得分与失分原因、是否存在无法破解的固定策略。先确认玩家能理解胜负并愿意再来一局，再增加地图和更多规则。

本文完成的是资料核对、现有代码适配分析与原型规则设计；尚无新增玩法的运行证据，不能把表中的模式写成已上线功能。
